# Contract: Calendar file (`Anniversary.Calendar.*.json`)

The calendar file format as built on 2026-10-09, v4's format plus optional metadata
(`Anniversary.Shared/Model/CalendarData.cs`), and the ten files shipped with it, as they were at the move to GitHub
(`67a4092`). Behaviour: [spec.md](../spec.md); entities: [data-model.md](../data-model.md); system spec:
[docs/spec.md](../../../docs/spec.md) 5.1 and 5.7.

## File name and places

- `Anniversary.Calendar.{Name}.json`. Without a `name` inside, the menu shows `{Name}`.
- Looked for in this order: next to the executable; in the app-data folder (`%APPDATA%\Anniversary` on Windows,
  `~/Library/Application Support/Anniversary` on macOS, `~/.config/Anniversary` on Linux); among the calendars built
  into the app. The first file of a name wins (names are compared case-insensitively), so a user's file replaces a
  shipped one of the same name.
- `calendarFile` in `appsettings.json` may also give a full path. Such a file is used as is and needn't follow the
  naming pattern.
- The app never writes or changes a calendar file.

## Content

```json
{
  "name": "Czechia (Česko)",
  "locale": "cs-CZ",
  "source": "Anniversary v4 (Anniversary.Calendar.Czech.json)",
  "license": "MIT, Copyright (c) David Pokluda (part of Anniversary; see LICENSE)",
  "calendar": {
    "01-01": "Nový rok",
    "01-02": "Karina",
    "10-09": "Štefan/Sára",
    "12-24": "Adam a Eva/Štědrý den"
  }
}
```

(an excerpt of the shipped Czech file)

| Key | Type | Required | Meaning |
|---|---|---|---|
| `name` | string | no (**new**) | the display name in the menu; when missing, taken from the file name |
| `locale` | string | no (**new**) | a culture code such as `cs-CZ`; informational, "reserved for automatic choice by OS locale later" (spec 5.1) |
| `source` | string | no (**new**); every shipped calendar has it | where the data came from |
| `license` | string | no (**new**); every shipped calendar has it | the terms of the data |
| `calendar` | object | yes (v4) | the day key → the text shown for that day |

- Day keys are `MM-dd`: up to 366 entries, `02-29` included. Days without names may be missing; they show nothing.
- A value is display text and may contain `,` or `/` (`"Štefan/Sára"`, `"Dénes, János"`). Next N days splits it at the
  commas (spec 6.1).
- Read with case-insensitive property names; comments and trailing commas are allowed. A v4 file, which has only
  `calendar`, loads unchanged.

## Errors

| Situation | Result |
|---|---|
| The file can't be read or isn't valid JSON | not offered in the menu; if it is the active calendar: the warning `Error loading calendar: {message}` and no calendar names |
| The active calendar isn't found | the warning `Calendar file not found: {name}` and no calendar names |

The warnings are shown in a message titled **Data Error** ([calendar-menu.md](calendar-menu.md)).
