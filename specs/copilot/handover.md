## Where things stand

Anniversary v5 is a cross-platform rewrite of the WinForms v4 app (`Tools/csharp/Anniversary.v4` in the old `pokluda`
repository) using **Avalonia 12.1.4 on .NET 10**. **Phase 1 (desktop) is done** and verified on Windows, macOS and
Linux.

## What the app does (short)

The main window shows "Today is" (date and the calendar's name-day names), Namedays, Birthdays and Anniversaries, and
"Next N days", with Yesterday, Tomorrow and Quit buttons. A **⋯** button (top-right; also on right-click) opens the
commands menu:
- Today, Change Date…, Find… (Ctrl/⌘+F), Find Next (F3/⌘G)
- Edit People… (a grid editor with an Anniversaries sub-dialog)
- Nameday Calendar ▸, Theme ▸ System/Light/Dark
- About

macOS also has the commands in the menu bar (`NativeMenu`); Windows and Linux ignore it.

Data files are looked up next to the exe, then in the app-data folder (`%APPDATA%\Anniversary`,
`~/Library/Application Support/Anniversary`, `~/.config/Anniversary`), then in built-in defaults. The built-in people
list is empty; to see real data, copy v4's `Anniversary.Data.json` into the app-data folder. The app writes only
`usersettings.json` (theme and calendar) and, from the editor, `Anniversary.Data.json`.

## Decisions already made (don't revisit without asking the user)

- Avalonia, not MAUI/Uno. Three projects. **Code-behind, no MVVM**, no DI, no mocking library.
- All non-UI logic lives in one class, `AnniversaryBook`. The editor row classes `PersonRow` and `AnniversaryRow` are
  the only extra types.
- Dates are `DateOnly`, passed in. No `TimeProvider`.
- Coding style follows v4: Allman braces, braces on every `if`, `_camelCase` fields, file-scoped namespaces.
- XML docs on every type and public member. Tests use the classic style: real objects and temp files.
- The look blends with the OS:
  - Fluent `DensityStyle="Compact"`.
  - `AppFontSize` is 12 on Windows and **13 on macOS/Linux**, set in `App.Initialize`.
  - The window is 312 × 468 DIPs (v4's size); 312 × 492 on macOS, with a 12 px margin.
  - Menu text and separators are aligned; separators use a subtle gray.
  - The calendar drop-down is scaled down.
- Years aren't shown when the date's year is after the displayed day (`9999` means "unknown year" in v4 data).
- **Platform-specific look values are resources set in `App.Initialize`** (spec 7.1): `AppFontSize`,
  `AppNamesFontSize`, `AppDateFontSize`, `AppCaptionFontSize`, `AppStrongFontWeight`, the `App…LineHeight` resources,
  `AppWindowMargin`, `AppWindowHeight`, and on macOS also `ContentControlThemeFontFamily` and `ControlCornerRadius`.
  Windows and Linux use the defaults. A platform fix adds an `OperatingSystem.Is…()` block there and keeps the other
  platforms' looks unchanged.

## Lessons from the macOS look fixes (useful for any new platform, including iOS)

- **Avalonia uses Skia's default font, not necessarily the desktop's UI font.** On macOS that was Helvetica. On Linux,
  Skia asks fontconfig for the default `sans-serif`.
- **Variable fonts:** Avalonia takes glyph advances from a variable font's regular instance, so its **bold/semibold
  text is drawn cramped** (seen with macOS's SF). The fix is a static font, the way macOS uses Helvetica Neue.
- **Missing weights fall back to bold:** a font without semibold draws `SemiBold` names as Bold. macOS uses Medium via
  `AppStrongFontWeight`.
- **Tight line boxes:** with a font whose line height is small (Helvetica Neue ≈ 1.17 em) accents on capitals (the
  caron on *Š* in "Štefan/Sára", 9 October) touch the line above, and "Next N days" looks cramped. macOS sets the
  `App…LineHeight` resources to 4/3 of the font size (Segoe UI's ratio).
- **Window corners:** large rounded window corners crowd the bottom buttons at an 8 px margin (`AppWindowMargin`).
- **Headless renders for comparing variants:** render the main window off-screen with `Avalonia.Headless` +
  `Avalonia.Skia` (`UseHeadless(new AvaloniaHeadlessPlatformOptions { UseHeadlessDrawing = false })`, then
  `RenderTargetBitmap` at 192 DPI). It uses the real system font manager, so it shows the same fonts as the app.
  Handy when the agent can't take screenshots; keep such a harness outside the repo.

## Avalonia 12 gotchas

- `NativeMenuItem` has no routed `Click` event and gets no generated fields, so `MainWindow` finds the macOS menu items by
  header and wires them in code.
- Both menu kinds use the same `MenuItemToggleType` enum for radio items.
- Values set inside control templates can't be overridden by styles. The calendar's and the menu chevron's sizes are fixed
  by `TemplateApplied` class handlers in `App.axaml.cs`.
- `DataGridCollectionView.Refresh()` throws during an edit. The editor commits the edit first and refreshes only when the
  filter text really changed.
- xUnit v3 on the .NET 10 SDK needs `global.json` to use Microsoft.Testing.Platform, so run
  `dotnet test --project Anniversary.Tests`.

## Setting up on any OS

Install the .NET 10 SDK (Fedora: `sudo dnf install dotnet-sdk-10.0`; otherwise https://dotnet.microsoft.com/download),
then:

```bash
git clone https://github.com/dpokluda/anniversary.git && cd anniversary
dotnet build Anniversary.slnx
dotnet test --project Anniversary.Tests      # expect 78 passed
dotnet run --project Anniversary.Desktop
```

On Linux the app needs fontconfig, libX11, libICE and libSM, which Fedora Workstation already has. Avalonia runs as an
X11 app, through XWayland on GNOME's Wayland session.

Every CI run also offers ready-to-run builds (README, "Downloading a build"), so trying a change on another OS doesn't
need the SDK there.

## Things that need Windows

- `icon/Build-Icon.ps1` uses System.Drawing (GDI+), so it's Windows-only. The generated icon files are committed.
- `calendars/Build-Calendars.ps1` is PowerShell 7 and should run on macOS and Linux too, but it hasn't been tried
  there. The generated files are committed.

## Known issues (found in review, not fixed yet)

- **Dates at the ends of `DateOnly`'s range crash the app.** `GetDay` looks N days ahead with `AddDays`, which overflows
  in the last days of year 9999; `Find` builds `new DateOnly(from.Year + 1, 12, 31)`, which fails for 9999; and
  Yesterday/Tomorrow/Find Next overflow at 0001-01-01 and 9999-12-31. Only reachable by choosing such a date in Change
  Date. A fix belongs in `AnniversaryBook` (plus the main window's day buttons), with tests.

   International Days calendar.
3. **Phase 2: iOS** (`Anniversary.iOS` next to `Anniversary.Desktop`). It needs Xcode on the Mac and a single-view
   lifetime, and the dialogs become overlays (spec 1 and 8).
4. **Later: installers and start at login** (`specs/plan.md`, requested, not started): an installer per platform and
   an in-app Start at Login setting.
