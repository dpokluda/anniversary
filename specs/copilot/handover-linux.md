## Where things stand

Anniversary v5 is a cross-platform rewrite of the WinForms v4 app (`Tools/csharp/Anniversary.v4` in the old `pokluda` repository) using **Avalonia 12.1.4
on .NET 10**. **Phase 1 (desktop) is implemented and verified on Windows.** It also runs on macOS, where its look has been
fixed. What's left in phase 1 is the Linux check and the rest of the macOS check list.

## What the app does (short)

The main window shows "Today is" (date and the calendar's name-day names), Namedays, Birthdays and Anniversaries, and
"Next N days", with Yesterday, Tomorrow and Quit buttons. A **⋯** button (top-right; also on right-click) opens the
commands menu:
- Today, Change Date…, Find… (Ctrl/⌘+F), Find Next (F3/⌘G)
- Edit People… (a grid editor with an Anniversaries sub-dialog)
- Nameday Calendar ▸, Theme ▸ System/Light/Dark
- About

On Linux there's no menu bar: the `NativeMenu` used on macOS is ignored, so everything goes through the ⋯ menu.

Data files are looked up next to the exe, then in the app-data folder, then in built-in defaults. On Linux the app-data
folder is `~/.config/Anniversary`. The built-in people list is empty. The app writes only `usersettings.json` (theme
and calendar) and, from the editor, `Anniversary.Data.json`.

## Decisions already made (don't revisit without asking the user)

- Avalonia, not MAUI/Uno. Three projects. **Code-behind, no MVVM**, no DI, no mocking library.
- All non-UI logic lives in one class, `AnniversaryBook`. The editor row classes `PersonRow` and `AnniversaryRow` are
  the only extra types.
- Dates are `DateOnly`, passed in. No `TimeProvider`.
- Coding style follows v4: Allman braces, braces on every `if`, `_camelCase` fields, file-scoped namespaces.
- XML docs on every type and public member. Tests use the classic style: real objects and temp files.
- The look blends with the OS:
  - Fluent `DensityStyle="Compact"`.
  - `AppFontSize` is 12 on Windows and **13 on macOS/Linux**, set in `App.Initialize`.
  - The window is 312 × 468 DIPs (v4's size); 312 × 492 on macOS, with a 12 px margin.
  - Menu text and separators are aligned; separators use a subtle gray.
  - The calendar drop-down is scaled down.
- Years aren't shown when the date's year is after the displayed day (`9999` means "unknown year" in v4 data).
- **Platform-specific look values are resources set in `App.Initialize`** (spec 7.1): `AppFontSize`,
  `AppNamesFontSize`, `AppDateFontSize`, `AppCaptionFontSize`, `AppStrongFontWeight`, the `App…LineHeight` resources,
  `AppWindowMargin`, `AppWindowHeight`, and on macOS also `ContentControlThemeFontFamily` and `ControlCornerRadius`.
  Windows and Linux currently use the defaults; a Linux fix should add an `OperatingSystem.IsLinux()` block there.

## What was learned on macOS (likely relevant on Linux)

- **Avalonia uses Skia's default font, not necessarily the desktop's UI font.** On macOS that was Helvetica. On Fedora,
  Skia asks fontconfig for the default `sans-serif`, which should be the GNOME font (Adwaita Sans on Fedora 42+,
  Cantarell before), but check it.
- **Variable fonts:** Avalonia takes glyph advances from a variable font's regular instance, so its **bold/semibold text
  is drawn cramped** (seen with macOS's SF). If the Fedora font is variable and the bold date ("Friday, October 9, 2026")
  looks squeezed, pick a static font (for example via fontconfig `sans-serif` matching a static family) the way macOS
  uses Helvetica Neue.
- **Missing weights fall back to bold:** a font without semibold draws `SemiBold` names as Bold. macOS uses Medium via
  `AppStrongFontWeight`.
- **Tight line boxes:** with a font whose line height is small (Helvetica Neue ≈ 1.17 em) accents on capitals (the
  caron on *Š* in "Štefan/Sára", 9 October) touch the line above, and "Next N days" looks cramped. macOS sets the
  `App…LineHeight` resources to 4/3 of the font size (Segoe UI's ratio).
- **Window corners:** large rounded window corners crowd the bottom buttons at an 8 px margin (`AppWindowMargin`).
- **Headless renders for comparing variants:** the Mac session rendered the main window off-screen with
  `Avalonia.Headless` + `Avalonia.Skia` (`UseHeadless(new AvaloniaHeadlessPlatformOptions { UseHeadlessDrawing = false })`,
  then `RenderTargetBitmap` at 192 DPI). It uses the real system font manager, so it shows the same fonts as the app.
  Handy when the agent can't take screenshots; keep such a harness outside the repo.

## Avalonia 12 gotchas learned on Windows

- `NativeMenuItem` has no routed `Click` event and gets no generated fields, so `MainWindow` finds the macOS menu items by
  header and wires them in code.
- Both menu kinds use the same `MenuItemToggleType` enum for radio items.
- Values set inside control templates can't be overridden by styles. The calendar's and the menu chevron's sizes are fixed
  by `TemplateApplied` class handlers in `App.axaml.cs`.
- `DataGridCollectionView.Refresh()` throws during an edit. The editor commits the edit first and refreshes only when the
  filter text really changed.
- xUnit v3 on the .NET 10 SDK needs `global.json` to use Microsoft.Testing.Platform, so run
  `dotnet test --project Anniversary.Tests`.

## Setting up Fedora

Option A: run a build published on the Mac (no .NET needed on Fedora). Use `linux-x64` on a PC and `linux-arm64` in a
virtual machine on Apple Silicon (UTM, Parallels):

```bash
dotnet publish Anniversary.Desktop -c Release -r linux-arm64 --self-contained -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true -o publish/linux-arm64      # on the Mac; or linux-x64
# copy the folder (keep THIRD-PARTY-NOTICES.md next to the exe), then on Fedora:
chmod +x Anniversary && ./Anniversary
```

Option B: build on Fedora (needed for the agent to fix things there):

```bash
sudo dnf install dotnet-sdk-10.0 git     # or https://dotnet.microsoft.com/download/dotnet/10.0
dotnet --list-sdks                       # needs 10.0.x

git clone https://github.com/dpokluda/anniversary.git && cd anniversary
dotnet build Anniversary.slnx
dotnet test --project Anniversary.Tests      # expect 78 passed
dotnet run --project Anniversary.Desktop
```

The app needs fontconfig, libX11, libICE and libSM, which Fedora Workstation already has. Avalonia runs as an X11 app,
through XWayland on GNOME's Wayland session; that's expected.

To see real data, copy your `Anniversary.Data.json` (v4's file, from the `pokluda` repository) into `~/.config/Anniversary/` (create the
folder).

**`linux-arm64` isn't in the README or the spec's RID list yet** (spec 10: `win-x64`, `osx-arm64`, `osx-x64`,
`linux-x64`). If it's used, add it to both.

## What to check on Linux (spec section 12)

1. **Starts and looks right:** GNOME title bar, layout as on Windows. Compare with the preview mocks in `specs/screens/`
   (the user has a screenshot of the real v5 Windows look). Check especially:
   - which font is used, and whether the bold date looks cramped;
   - whether "Štefan/Sára" (9 October) shows the caron clearly and "Next 7 days" isn't too tight;
   - the bottom buttons' clearance from the window corners.
2. **⋯ button and right-click menu:** they work, the separators line up with the text, the submenus (Nameday Calendar,
   Theme) open, the radio check marks follow the current choice.
3. **Shortcuts:** Ctrl+F, F3.
4. **Theme:** with Theme set to **System**, switching GNOME's Light/Dark style (Settings ▸ Appearance) re-themes the
   running app. Light and Dark persist across restarts.
5. **Data:** files in `~/.config/Anniversary` are used. Edit People saves there, and the main window updates.
6. **Dialogs:** Change Date (the calendar drop-down opens below and is compact), Find, About (shows the icon). Dialogs
   should be modal and centred on the main window.
7. **Resizing:** only "Next N days" grows taller.
8. **Window icon:** the taskbar/alt-tab icon. Without a `.desktop` file GNOME may show a generic icon; note it, don't
   fix it yet.

Anything that looks off: fix it in `Anniversary.Shared` and keep the Windows and macOS looks unchanged. Platform-specific
values go through `OperatingSystem.IsLinux()` and the resources in `App.Initialize`. After a fix, update `specs/spec.md`
and rerun the tests.
